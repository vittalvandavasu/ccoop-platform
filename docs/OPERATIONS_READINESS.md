## Prepared restore drill (not executed)

DBA chooses approved RPO/RTO and backup source. Record commit/schema ledger, backup timestamp and restricted manifest. Restore with native PostgreSQL tooling into a new isolated database, using a protected connection service/password file (not CLI secrets). Inspect `schema_migrations` before starting application auto-migration. Take a second isolated copy for upgrade and interruption tests. Never seed or run truncating tests against a restored real-data database. Restrict access and mask data according to approved privacy rules.

Compare per-order `paid` with summed `credited_amount`; retained event IDs/provider references/counts, exceptions/holds, obligations, snapshots, receipt lines, movement totals, allocation and pickup history. Verify no negative/overallocated stock. Existing legacy inconsistencies require investigation, not automatic rewrites. Restore worker with outbound provider access disabled first; inspect pending leases/jobs. Only an authorized sandbox operator enables verification against matching sandbox records. Never replay real payments into an unrelated restored environment. Record time-to-restore, accepted loss window and owner sign-off. Destruction of backups/restored evidence follows separately approved retention.

## Prepared incident sequence (not deployed)

1. Incident commander assigns severity and responders; preserve restricted logs, commit/config fingerprints and DB/provider correlation IDs without secrets.
2. Platform uses the preapproved, rehearsed ingress rule to stop new payment creation. Keep signed callbacks and authenticated reconciliation working if safe. Do not select simulator as a kill switch, clear holds or edit paid/stock counters.
3. Payments owner checks provider state against immutable local events. DBA investigates availability, locks, audit-write failures and backup recovery options. Restart/reclaim worker leases only with the original database and provider identity intact.
4. Finance/fulfillment owners retain unresolved holds; use the decision register for any later disposition. Escalate exhausted jobs manually; a new reasoned reconciliation request is allowed after prior work terminates.
5. Engineering fixes forward, repeats affected regression and reconciliation checks; incident commander authorizes reopening only after financial/stock invariants and outstanding provider sessions are reviewed. Record cause, timeline and follow-up. No actual pause/reopen occurred in this audit.
